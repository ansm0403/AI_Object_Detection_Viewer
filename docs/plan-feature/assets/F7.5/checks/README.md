# F7.5 화면 확인 스크립트

실제 앱을 브라우저로 조작해 항목마다 `PASS` / `FAIL`을 찍는 스크립트다(Playwright). F7.5 세션에서 단계마다 쓰고
마지막 빌드에서 전부 다시 돌린 것을 그대로 옮겼다. F7 때는 스크립트가 임시 폴더에만 있다가 사라져서, 다음 기능이
기존 화면을 깨뜨렸는지 확인하려면 새로 써야 했다. 그래서 저장소에 둔다.

**이 스크립트는 F7.5 시점의 화면을 기준으로 한다.** 화면의 글자(영어)와 버튼 이름으로 요소를 찾으므로, 뒤 기능이
화면을 바꾸면 낡는다. 실패가 나오면 앱 문제인지 스크립트가 낡은 것인지부터 가린다.

| 파일 | 확인하는 것 | 항목 |
|---|---|---|
| `lib.js` | 공통 도구(브라우저 띄우기, 통과/실패 기록, 글자 잘림 확인) | |
| `b.js` | 헛짚음 표본 검수(목록, 판정, 단축키, 다른 카메라 보기, 내보내기, 좁은 폭) | 154 |
| `c.js` | IoU 0.3 / 0.5 고르기, 조건 한 줄, 고정된 숫자 | 74 |
| `d.js` | 평가 보고서 창(주행 표, 같은 거리끼리의 낮/밤) | 51 |
| `edge.js` | 엣지 케이스(장면이 늦게 오거나 실패할 때, 빠른 연타, 390px, 저장이 안 될 때, 옛 형식과 깨진 저장값) | 48 |
| `reg.js` | F4~F7의 기존 흐름(검수, 평가, 카메라 6대, 장면 탐색) | 30 |
| `perf.js` | 3D 바닥 비용(그리기 호출 41 / 42번) | 5 |

합계 362항목. 마지막으로 돌린 결과는 `../2026-11-27_steps/*_checks.txt`와 `../2026-11-27_edge/*_checks.txt`에 있다.

## 돌리는 방법

1. 배포용 빌드를 만들어 **3100번 포트**에 띄운다(3000번은 개발 서버 자리라 쓰지 않는다).

   ```bash
   cd apps/ai_detection_viewer_client
   npx next build --webpack
   npx next start -p 3100
   ```

   빌드가 `next-env.d.ts`를 바꾸면 되돌린다(`git checkout -- next-env.d.ts`).

2. 다른 터미널에서, 저장소 안에서 스크립트를 돌린다.

   ```bash
   node docs/plan-feature/assets/F7.5/checks/reg.js
   ```

   마지막 줄이 `reg: 30 / 30 passed` 모양이면 통과다.

3. 끝나면 3100번 서버를 끈다.

## 알아 둘 것

- `playwright`는 저장소의 `node_modules`에서 찾는다(루트 `package.json`의 `@playwright/test`에 딸려 온다).
  그래서 저장소 밖으로 복사해 돌리면 찾지 못한다.
- 캡처, 결과 파일, 내려받은 내보내기 파일은 저장소에 쓰지 않는다. 기본은 시스템 임시 폴더의
  `ai-detection-viewer-checks/`이고, `CHECK_OUT=<폴더>`로 바꾼다. 주소는 `CHECK_URL`로 바꾼다(기본 `http://localhost:3100`).
- 브라우저는 GPU 없이 소프트웨어로 그린다(`--use-angle=swiftshader`). 시간에 관한 숫자는 참고값이다.
- 스크립트마다 새 브라우저를 띄우므로 사용자의 브라우저에 저장된 판정은 건드리지 않는다.
- 스크립트가 통과해도 캡처를 눈으로 본다. 통과한 화면에서 글자가 잘려 있던 적이 있다(`Edge_F#7.5.md`).
