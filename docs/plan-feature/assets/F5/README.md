# F5 화면 기록 (시안과 캡처)

F5(카메라 탐지 평가)를 진행하면서 만든 시안과 실제 앱 캡처를 남긴다. 화면에 관한 결정을 무엇을 보고 내렸는지
나중에 확인하기 위한 기록이다. 설계는 [../../F5_camera_detection_eval.md](../../F5_camera_detection_eval.md)에 있다.

- 시각은 모두 **한국 시간(KST, UTC+9)** 이다.
- 캡처는 Playwright(Chromium, `--use-angle=swiftshader`)로 찍었다. 방법은 `../../HANDOFF.md` 8장.
- 원본 PNG를 1:1 크기 그대로 JPEG(품질 80)로 다시 저장했다. 폴더 전체가 이미지 42장과 페이지 3개로 약 6.3MB다
  (시안과 사전 캡처 13장, 단계별 24장, 엣지 검증 5장).
- 모든 화면은 **프레임 6**이다(보행자, 오토바이, 차가 모두 앞 카메라에 보이는 프레임).
- 선택한 객체: 놓친 오토바이 `599909…`(24m), 찾은 보행자 `af7483…`(27m, 모델 점수 0.81),
  헛짚음 "person 0.35"(34m 거리의 오토바이 정답 위에 그려진 모델 박스).

## 보는 방법

| 페이지 | 내용 |
|---|---|
| **[compare.html](compare.html)** | 구현 **전**: "지금(F4 완료 화면) ↔ 시안"을 같은 자리에서 바꿔 본다. 설계 문서의 화면 결정(1~4)을 승인받을 때 쓴다 |
| **[steps.html](steps.html)** | 구현 **중**: 단계가 끝날 때마다 찍은 **실제 앱** 화면. 시안이 있는 화면은 `Space`로 시안과 비교된다 |

이미지를 클릭하거나 `Space`를 누르면 전환되고, 숫자키로 화면을 고른다. 이미지는 실제 크기(1:1)다.

## 2026-11-25_mockup — 화면 시안 (22:53~22:54 KST)

**실제 앱을 띄운 뒤 그 화면 위에 제안하는 UI를 그려 넣고 찍은 것**이다. 화면 틀, 사진, LiDAR 점, 크기는 실제 앱의 것이다.

- **숫자는 모두 실제 값이다.** 이 컴퓨터에서 YOLOv8n(입력 1280)을 사진 10장에 돌린 결과를 설계 문서의 추천 규칙
  (점수 0.25 이상, 같은 클래스, IoU 0.3 이상, 가시성 0~40% 채점 제외)으로 채점했다.
- **3D 박스의 색도 실제 장면에서 바꾼 것이다.** three.js가 개발 도구용으로 내보내는 신호(`__THREE_DEVTOOLS__`)로
  장면 객체를 얻어, 박스 선의 색을 결과에 맞춰 바꾼 뒤 찍었다.
- 카메라 칸의 박스는 실제 정답 박스(3D 박스를 비춘 사각형)와 실제 YOLO 박스다.
- 그려 넣은 UI의 글자 폭과 칸 폭은 근사치다. 1024px에서 목록의 클래스 이름이 잘리는 것은 구현에서 조정한다.

| 파일 (접두어) | 상태 | 남긴 창 크기 |
|---|---|---|
| `A1_missed_zoom` | **추천안(평가 모드).** 놓친 오토바이 선택, 카메라 확대 | 1536×700, 1024×768 |
| `A2_missed_full` | A1과 같고 카메라만 전체 보기 | 1536×700 |
| `A3_found_zoom` | 찾은 보행자 선택. 정답(점선)과 모델(실선)이 겹쳐 보임 | 1536×700 |
| `A4_falsealarm_zoom` | 헛짚음 선택. 3D에는 선택 표시가 없음 | 1536×700 |
| `B1_tab_missed_zoom` | **대안.** 정보 패널 안에만 탭을 둔 방식 | 1536×700 |
